⏱ 45–60 menit📶 Pemula🧩 Docker, AWS CLI, Floci
Penjelasan sederhana

Sebelum belajar menyetir, Anda perlu mobil latihan dan kunci kontak. Di sini Floci adalah mobil latihannya (AWS tiruan di laptop), AWS CLI adalah setirnya (alat untuk memberi perintah ke AWS lewat terminal), dan kredensial adalah kunci kontaknya. Untuk Floci, kuncinya boleh apa saja, misalnya test.

Tujuan modul

  • Floci berjalan di http://localhost:4566.
  • AWS CLI v2 terpasang dan diarahkan ke Floci, bukan ke AWS asli.
  • Paham dari mana CLI mengambil kredensial, region, dan endpoint.
  • Python + boto3 siap untuk modul-modul berikutnya.

Apa yang terjadi saat Anda mengetik perintah AWS?

Langkah praktik

Panduan lebih rinci: pemasangan per sistem operasi, Docker Compose, menyimpan data, dan solusi masalah ada di halaman Menjalankan di Laptop.
Pengguna Windows: sangat disarankan mengerjakan semua modul di terminal WSL (Ubuntu). Perintah di kursus ini ditulis untuk bash. Tab PowerShell disediakan untuk langkah-langkah penting.

Pasang dan cek Docker

Floci dijalankan sebagai container Docker. Di Windows, pasang Docker Desktop dan aktifkan Settings → Resources → WSL integration untuk distro Ubuntu Anda. Lalu cek:

docker version
docker run --rm hello-world
Hello from Docker!
This message shows that your installation appears to be working correctly.
...

Pasang AWS CLI versi 2

AWS CLI adalah program resmi dari AWS. Kita memakai versi 2 karena mendukung variabel AWS_ENDPOINT_URL.

curl "https://awscli.amazonaws.com/awscli-exe-linux-x86_64.zip" -o awscliv2.zip
unzip -q awscliv2.zip
sudo ./aws/install
aws --version
msiexec.exe /i https://awscli.amazonaws.com/AWSCLIV2.msi
# tutup lalu buka lagi PowerShell, kemudian:
aws --version
curl "https://awscli.amazonaws.com/AWSCLIV2.pkg" -o AWSCLIV2.pkg
sudo installer -pkg AWSCLIV2.pkg -target /
aws --version
aws-cli/2.x.x Python/3.x.x Linux/... exe/x86_64...

Kalau yang muncul aws-cli/1.x, Anda memakai versi lama. Hapus dulu (pip uninstall awscli) lalu pasang versi 2.

Nyalakan Floci

Perintah ini menjalankan Floci di port 4566. Opsi -v /var/run/docker.sock… dan -u root memberi Floci akses ke Docker. Ini wajib untuk Modul 5 (Lambda), karena setiap fungsi Lambda dijalankan sebagai container.

docker run -d --name floci \
  -p 4566:4566 \
  -v /var/run/docker.sock:/var/run/docker.sock \
  -u root \
  floci/floci:latest

docker logs floci | tail -5      # lihat log
curl -s http://localhost:4566/_floci/health
{"services":{"s3":"running","sqs":"running", ... },"edition":"community","version":"..."}

Perintah penting lain yang akan sering dipakai:

PerintahFungsi
docker stop floci / docker start flociMematikan / menyalakan lagi
docker rm -f floci lalu docker run … lagiReset total: semua bucket, antrean, tabel hilang (mode default menyimpan di memori)
docker logs -f flociMelihat log secara langsung (Ctrl+C untuk keluar)

Arahkan AWS CLI ke Floci

Ada dua cara. Pilih salah satu. Cara A paling cepat; cara B lebih rapi untuk jangka panjang.

export AWS_ENDPOINT_URL=http://localhost:4566
export AWS_DEFAULT_REGION=us-east-1
export AWS_ACCESS_KEY_ID=test
export AWS_SECRET_ACCESS_KEY=test

# agar permanen, tambahkan 4 baris di atas ke ~/.bashrc

$env:AWS_ENDPOINT_URL      = "http://localhost:4566"
$env:AWS_DEFAULT_REGION    = "us-east-1"
$env:AWS_ACCESS_KEY_ID     = "test"
$env:AWS_SECRET_ACCESS_KEY = "test"
# ~/.aws/config
[profile floci]
region = us-east-1
endpoint_url = http://localhost:4566

# ~/.aws/credentials
[floci]
aws_access_key_id = test
aws_secret_access_key = test

# lalu aktifkan profilnya:
export AWS_PROFILE=floci

Cek dari mana nilai-nilai diambil:

aws configure list
      Name                    Value             Type    Location
      ----                    -----             ----    --------
   profile                <not set>             None    None
access_key     ****************test              env
secret_key     ****************test              env
    region                us-east-1              env    AWS_DEFAULT_REGION
Penting: tanpa AWS_ENDPOINT_URL, CLI akan menghubungi AWS asli di internet. Dengan kredensial test request itu pasti ditolak, jadi aman, tetapi Anda akan bingung melihat errornya. Kalau ragu, tambahkan --endpoint-url http://localhost:4566 di akhir perintah.

Uji koneksi pertama

sts get-caller-identity adalah perintah "siapa saya?". Di AWS asli ini cara cepat mengecek kredensial.

aws sts get-caller-identity
aws s3 ls
{
    "UserId": "000000000000",
    "Account": "000000000000",
    "Arn": "arn:aws:iam::000000000000:root"
}

aws s3 ls tidak mencetak apa-apa karena belum ada bucket. Itu tandanya berhasil. Anda dikenali sebagai root (pemilik akun) di akun 000000000000.

Siapkan Python + boto3

boto3 adalah SDK resmi AWS untuk Python. Kode aplikasi memakai SDK, bukan CLI. boto3 juga membaca AWS_ENDPOINT_URL, jadi kode yang sama berjalan di Floci maupun AWS asli.

python3 -m venv ~/belajar-aws          # jika error: sudo apt install python3-venv
source ~/belajar-aws/bin/activate
pip install boto3

cat > cek.py <<'EOF'
import boto3
sts = boto3.client("sts")
print(sts.get_caller_identity()["Arn"])
EOF
python cek.py
arn:aws:iam::000000000000:root

Latihan mandiri

Latihan 1. Buka terminal baru, jangan set variabel apa pun, lalu jalankan aws s3 ls --endpoint-url http://localhost:4566. Apa yang terjadi, dan kenapa?
Lihat kunci jawaban

Muncul Unable to locate credentials (atau diminta region). Walaupun Floci menerima kredensial apa pun, AWS CLI sendiri menolak mengirim request tanpa kredensial, karena setiap request AWS harus ditandatangani (SigV4). Jadi kredensial palsu tetap wajib ada.

Latihan 2. Ubah AWS_ACCESS_KEY_ID menjadi 111111111111 (12 digit), lalu jalankan aws sts get-caller-identity. Akun apa yang muncul?
Lihat kunci jawaban

"Account": "111111111111". Floci memakai access key 12 digit sebagai nomor akun. Ini cara mudah mensimulasikan beberapa akun AWS: resource di akun 111111111111 tidak terlihat dari akun 000000000000. Kembalikan ke test setelah selesai.

Kuis

1. Apa fungsi AWS_ENDPOINT_URL=http://localhost:4566?
Endpoint adalah alamat tujuan request. Dengan variabel ini semua layanan diarahkan ke Floci.
2. Kenapa Floci perlu -v /var/run/docker.sock:/var/run/docker.sock?
Beberapa layanan dijalankan sebagai container sungguhan. Untuk data permanen dipakai volume /app/data dan mode storage.
3. aws s3 ls tidak mencetak apa pun. Artinya?
Kalau ada error, CLI selalu mencetak pesan error dan keluar dengan kode bukan nol.

Ringkasan

  • Floci = AWS tiruan di localhost:4566. AWS CLI = alat perintah. boto3 = SDK Python.
  • CLI/SDK butuh 3 hal: kredensial, region, dan (khusus Floci) endpoint.
  • Reset total cukup dengan docker rm -f floci lalu jalankan lagi.
