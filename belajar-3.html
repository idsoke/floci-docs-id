📣 Modul 3 · SNS: Siaran ke Banyak Penerima

⏱ 45–60 menit📶 Pemula🧩 Amazon SNS (Simple Notification Service)
Penjelasan sederhana

SQS seperti surat ke satu orang. SNS seperti grup broadcast WhatsApp: Anda mengirim satu pesan ke grup (topic), dan semua anggota (subscriber) menerimanya sekaligus. Anggota bisa berupa antrean SQS, fungsi Lambda, alamat HTTP, atau email.

Pola "satu kirim, banyak terima" ini disebut fan-out. Contohnya: saat ada pesanan baru, dapur, bagian email, dan bagian laporan semuanya perlu tahu.

Tujuan modul

  • Membuat topic dan berlangganan (subscribe) dengan antrean SQS.
  • Melihat fan-out: satu publish sampai ke dua antrean.
  • Memahami "amplop" SNS dan opsi raw message delivery.
  • Memakai filter policy agar subscriber hanya menerima pesan yang relevan.

Konsep kunci

IstilahArti
TopicSaluran siaran. Diidentifikasi dengan ARN: arn:aws:sns:us-east-1:000000000000:pesanan-baru
SubscriptionPendaftaran satu penerima ke topic, dengan protokol (sqs, lambda, http, email, …)
PublishMengirim pesan ke topic
Message attributesLabel tambahan di luar isi pesan, mis. tipe=vip
Filter policyAturan di subscription: "kirim ke saya hanya jika atribut cocok"
SNS vs SQSSNS mendorong (push) ke banyak penerima, tidak menyimpan. SQS menyimpan sampai ada yang mengambil (pull).

Animasi: fan-out dengan filter

Langkah praktik

Buat topic

T=$(aws sns create-topic --name pesanan-baru --query TopicArn --output text)
echo $T
aws sns list-topics
arn:aws:sns:us-east-1:000000000000:pesanan-baru
{
    "Topics": [
        { "TopicArn": "arn:aws:sns:us-east-1:000000000000:pesanan-baru" }
    ]
}

Siapkan dua antrean penerima

B=http://localhost:4566/000000000000
for n in dapur email; do aws sqs create-queue --queue-name $n >/dev/null; done

ARN_DAPUR=$(aws sqs get-queue-attributes --queue-url $B/dapur --attribute-names QueueArn --query Attributes.QueueArn --output text)
ARN_EMAIL=$(aws sqs get-queue-attributes --queue-url $B/email --attribute-names QueueArn --query Attributes.QueueArn --output text)
echo $ARN_DAPUR $ARN_EMAIL
arn:aws:sqs:us-east-1:000000000000:dapur arn:aws:sqs:us-east-1:000000000000:email

Subscribe keduanya ke topic

aws sns subscribe --topic-arn $T --protocol sqs --notification-endpoint $ARN_DAPUR
aws sns subscribe --topic-arn $T --protocol sqs --notification-endpoint $ARN_EMAIL
aws sns list-subscriptions-by-topic --topic-arn $T --query 'Subscriptions[].Endpoint'
{
    "SubscriptionArn": "arn:aws:sns:us-east-1:000000000000:pesanan-baru:4b1e…"
}
...
[
    "arn:aws:sqs:us-east-1:000000000000:dapur",

]
Di AWS asli antrean juga harus punya queue policy yang mengizinkan topic SNS mengirim ke sana. Floci tidak memeriksa policy itu, jadi langkah tersebut dilewati di sini.

Publish dan lihat fan-out

aws sns publish --topic-arn $T --message '{"id": 7, "menu": "rendang"}'

aws sqs receive-message --queue-url $B/dapur --query 'Messages[0].Body' --output text
aws sqs receive-message --queue-url $B/email --query 'Messages[0].Body' --output text
{ "MessageId": "…" }
{"Type":"Notification","MessageId":"…","TopicArn":"arn:aws:sns:us-east-1:000000000000:pesanan-baru","Message":"{\"id\": 7, \"menu\": \"rendang\"}","Timestamp":"…",…}

Satu publish, dua antrean menerima. Perhatikan pesan asli Anda dibungkus amplop JSON SNS di field Message.

Raw message delivery (tanpa amplop)

SUB_DAPUR=$(aws sns list-subscriptions-by-topic --topic-arn $T \
  --query "Subscriptions[?Endpoint=='$ARN_DAPUR'].SubscriptionArn" --output text)
aws sns set-subscription-attributes --subscription-arn $SUB_DAPUR \
  --attribute-name RawMessageDelivery --attribute-value true

aws sns publish --topic-arn $T --message '{"id": 8, "menu": "gado-gado"}' >/dev/null
aws sqs receive-message --queue-url $B/dapur --query 'Messages[].Body' --output text
{"id": 8, "menu": "gado-gado"}

Sekarang antrean dapur menerima isi pesan apa adanya. Ini lebih mudah diproses oleh konsumen. (Antrean juga masih berisi pesan dari langkah sebelumnya jika belum dihapus.)

Filter policy: hanya pesanan VIP

aws sqs create-queue --queue-name vip >/dev/null
ARN_VIP=$(aws sqs get-queue-attributes --queue-url $B/vip --attribute-names QueueArn --query Attributes.QueueArn --output text)

aws sns subscribe --topic-arn $T --protocol sqs --notification-endpoint $ARN_VIP \
  --attributes '{"FilterPolicy": "{\"tipe\": [\"vip\"]}", "RawMessageDelivery": "true"}'

aws sns publish --topic-arn $T --message "pesanan biasa" \
  --message-attributes '{"tipe": {"DataType": "String", "StringValue": "biasa"}}'
aws sns publish --topic-arn $T --message "pesanan VIP!" \
  --message-attributes '{"tipe": {"DataType": "String", "StringValue": "vip"}}'

aws sqs receive-message --queue-url $B/vip --max-number-of-messages 10 --query 'Messages[].Body'
import boto3, json
sns, sqs = boto3.client("sns"), boto3.client("sqs")
topic = sns.create_topic(Name="pesanan-baru")["TopicArn"]   # idempoten: mengembalikan ARN yang sama
q = sqs.create_queue(QueueName="vip")["QueueUrl"]
arn = sqs.get_queue_attributes(QueueUrl=q, AttributeNames=["QueueArn"])["Attributes"]["QueueArn"]

sns.subscribe(TopicArn=topic, Protocol="sqs", Endpoint=arn, Attributes={
    "FilterPolicy": json.dumps({"tipe": ["vip"]}), "RawMessageDelivery": "true"})

for tipe in ["biasa", "vip"]:
    sns.publish(TopicArn=topic, Message=f"pesanan {tipe}",
                MessageAttributes={"tipe": {"DataType": "String", "StringValue": tipe}})

r = sqs.receive_message(QueueUrl=q, MaxNumberOfMessages=10, WaitTimeSeconds=2)
print([m["Body"] for m in r.get("Messages", [])])
[
    "pesanan VIP!"
]

Antrean vip hanya menerima pesan bertipe vip. Antrean dapur dan email (tanpa filter) tetap menerima keduanya.

Kesalahan umum

GejalaPenyebab
NotFound: Topic does not existARN topic salah, region berbeda, atau Floci sudah di-reset
Antrean tidak menerima apa punEndpoint subscription salah (harus ARN antrean, bukan URL), atau filter policy tidak cocok
InvalidParameter … FilterPolicyJSON filter policy tidak valid. Ingat: ini string JSON di dalam JSON.
Konsumen gagal mem-parsing pesanLupa bahwa pesan dibungkus amplop. Ambil field Message, atau aktifkan RawMessageDelivery.

Latihan mandiri

Latihan 1. Buat topic cuaca dengan tiga antrean penerima: jakarta, bandung, semua. Pasang filter agar jakarta hanya menerima kota=jakarta, bandung hanya kota=bandung, dan semua menerima semuanya.
Lihat kunci jawaban 
T2=$(aws sns create-topic --name cuaca --query TopicArn --output text)
for k in jakarta bandung semua; do
  aws sqs create-queue --queue-name $k >/dev/null
  A=$(aws sqs get-queue-attributes --queue-url $B/$k --attribute-names QueueArn --query Attributes.QueueArn --output text)
  if [ $k = semua ]; then ATTR='{"RawMessageDelivery":"true"}'
  else ATTR="{\"RawMessageDelivery\":\"true\",\"FilterPolicy\":\"{\\\"kota\\\":[\\\"$k\\\"]}\"}"; fi
  aws sns subscribe --topic-arn $T2 --protocol sqs --notification-endpoint $A --attributes "$ATTR" >/dev/null
done
for k in jakarta bandung; do
  aws sns publish --topic-arn $T2 --message "hujan di $k" \
    --message-attributes "{\"kota\":{\"DataType\":\"String\",\"StringValue\":\"$k\"}}" >/dev/null
done
for k in jakarta bandung semua; do echo "== $k"; aws sqs receive-message --queue-url $B/$k --max-number-of-messages 10 --query 'Messages[].Body' --output text; done

jakarta dan bandung masing-masing menerima satu pesan; semua menerima dua.

Latihan 2. Filter policy bisa memakai lebih dari satu nilai: {"tipe": ["vip", "gold"]}. Apa artinya?
Lihat kunci jawaban

Nilai dalam satu array berarti ATAU: pesan diterima jika tipe bernilai vip atau gold. Beberapa key yang berbeda (mis. tipe dan kota) berarti DAN: semuanya harus cocok.

Kuis

1. Satu event harus diproses oleh tiga sistem berbeda secara terpisah. Pola terbaik?
Satu antrean dengan tiga konsumen berarti setiap pesan hanya diproses oleh salah satu konsumen, bukan ketiganya.
2. Endpoint saat subscribe antrean SQS ke SNS adalah…
SNS mengidentifikasi tujuan SQS dengan ARN.
3. Kalau tidak ada subscriber saat publish, pesannya…
SNS hanya meneruskan. Gabungkan dengan SQS bila pesan harus disimpan.
