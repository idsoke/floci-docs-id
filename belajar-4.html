🗃️ Modul 4 · DynamoDB: Database NoSQL

⏱ 90 menit📶 Pemula–menengah🧩 Amazon DynamoDB
Penjelasan sederhana

Bayangkan lemari arsip dengan laci berlabel nama pelanggan. Untuk mencari arsip, Anda harus tahu label lacinya (partition key). Di dalam laci, arsip disusun urut berdasarkan tanggal (sort key), sehingga mudah mengambil "semua arsip Budi bulan November".

Inilah bedanya dengan database SQL: DynamoDB super cepat dan bisa sebesar apa pun, asalkan Anda mencari berdasarkan key. Mencari tanpa key (scan) berarti membuka semua laci satu per satu: lambat dan, di AWS asli, mahal.

Tujuan modul

  • Membuat tabel dengan partition key dan sort key.
  • Menulis dan membaca item (PutItem, GetItem).
  • Mencari dengan Query dan memahami kenapa Scan sebaiknya dihindari.
  • Mengubah sebagian item dengan UpdateItem.
  • Memakai antarmuka boto3 yang lebih ramah (Table resource).

Langkah praktik

Kita membuat tabel Pesanan: partition key pelanggan, sort key waktu (format ISO, sehingga urut alfabet = urut waktu).

Buat tabel

aws dynamodb create-table \
  --table-name Pesanan \
  --attribute-definitions AttributeName=pelanggan,AttributeType=S AttributeName=waktu,AttributeType=S \
  --key-schema AttributeName=pelanggan,KeyType=HASH AttributeName=waktu,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST \
  --query TableDescription.TableStatus

aws dynamodb list-tables
"ACTIVE"
{
    "TableNames": [
        "Pesanan"
    ]
}

Di AWS asli status awalnya CREATING selama beberapa detik. Gunakan aws dynamodb wait table-exists --table-name Pesanan dalam skrip agar aman. attribute-definitions hanya mendeskripsikan atribut key; atribut lain bebas.

Tulis item

CLI memakai format JSON "bertipe": setiap nilai dibungkus tipenya, mis. {"S": "budi"} atau {"N": "25000"}. Angka tetap ditulis sebagai string.

aws dynamodb put-item --table-name Pesanan --item '{
  "pelanggan": {"S": "budi"}, "waktu": {"S": "2026-11-01T08:00"},
  "menu": {"S": "nasi goreng"}, "total": {"N": "25000"}, "status": {"S": "baru"}}'

aws dynamodb put-item --table-name Pesanan --item '{
  "pelanggan": {"S": "budi"}, "waktu": {"S": "2026-11-02T12:30"},
  "menu": {"S": "soto"}, "total": {"N": "20000"}, "status": {"S": "baru"}}'

aws dynamodb put-item --table-name Pesanan --item '{
  "pelanggan": {"S": "budi"}, "waktu": {"S": "2026-10-20T19:00"},
  "menu": {"S": "bakso"}, "total": {"N": "18000"}, "status": {"S": "selesai"}}'

aws dynamodb put-item --table-name Pesanan --item '{
  "pelanggan": {"S": "sari"}, "waktu": {"S": "2026-11-01T09:15"},
  "menu": {"S": "rendang"}, "total": {"N": "35000"}, "status": {"S": "baru"}, "catatan": {"S": "pedas"}}'

Tidak ada output = sukses. Perhatikan item sari punya atribut catatan yang tidak dimiliki item lain. Itu boleh.

Hati-hati: put-item dengan key yang sama akan menimpa seluruh item tanpa peringatan. Pakai --condition-expression "attribute_not_exists(pelanggan)" jika ingin menolak penimpaan.

Baca satu item (GetItem)

aws dynamodb get-item --table-name Pesanan \
  --key '{"pelanggan": {"S": "sari"}, "waktu": {"S": "2026-11-01T09:15"}}'
{
    "Item": {
        "pelanggan": { "S": "sari" },
        "waktu":     { "S": "2026-11-01T09:15" },
        "menu":      { "S": "rendang" },
        "total":     { "N": "35000" },
        "status":    { "S": "baru" },
        "catatan":   { "S": "pedas" }
    }
}

GetItem butuh key lengkap (partition + sort). Jika item tidak ada, output-nya {}, bukan error.

Query: semua pesanan Budi di November

aws dynamodb query --table-name Pesanan \
  --key-condition-expression "pelanggan = :p AND begins_with(waktu, :bln)" \
  --expression-attribute-values '{":p": {"S": "budi"}, ":bln": {"S": "2026-11"}}' \
  --query 'Items[].[waktu.S, menu.S, total.N]' --output table
---------------------------------------------
|                   Query                   |
+-------------------+--------------+--------+
|  2026-11-01T08:00 |  nasi goreng |  25000 |
|  2026-11-02T12:30 |  soto        |  20000 |
+-------------------+--------------+--------+

Hasilnya terurut berdasarkan sort key. Tambahkan --no-scan-index-forward untuk urutan terbalik (terbaru dulu). Operator sort key lain: =, <, >, BETWEEN :a AND :b.

Ubah sebagian item (UpdateItem)

aws dynamodb update-item --table-name Pesanan \
  --key '{"pelanggan": {"S": "budi"}, "waktu": {"S": "2026-11-01T08:00"}}' \
  --update-expression "SET #st = :s ADD total :tambah" \
  --expression-attribute-names '{"#st": "status"}' \
  --expression-attribute-values '{":s": {"S": "dimasak"}, ":tambah": {"N": "5000"}}' \
  --return-values UPDATED_NEW
{
    "Attributes": {
        "status": { "S": "dimasak" },
        "total":  { "N": "30000" }
    }
}

status termasuk kata cadangan (reserved word) DynamoDB, jadi harus diganti alias #st. ADD menambah angka secara atomik, aman walau dua proses mengubahnya bersamaan.

Scan: mencari tanpa key (dan kenapa dihindari)

aws dynamodb scan --table-name Pesanan \
  --filter-expression "#st = :s" \
  --expression-attribute-names '{"#st": "status"}' \
  --expression-attribute-values '{":s": {"S": "baru"}}' \
  --query '{cocok: Count, dibaca: ScannedCount}'
{
    "cocok": 2,
    "dibaca": 4
}

ScannedCount (4) lebih besar dari Count (2): DynamoDB membaca seluruh tabel, lalu membuang yang tidak cocok. Dengan jutaan item, ini lambat dan di AWS asli Anda membayar semua item yang dibaca. Kalau sering mencari berdasarkan status, buat Global Secondary Index (GSI) dengan key status lalu pakai Query.

Python: antarmuka Table yang ramah

boto3.resource otomatis mengubah tipe Python ↔ format DynamoDB, jadi tidak perlu menulis {"S": …}.

import boto3
from boto3.dynamodb.conditions import Key, Attr
from decimal import Decimal

tabel = boto3.resource("dynamodb").Table("Pesanan")

tabel.put_item(Item={"pelanggan": "andi", "waktu": "2026-11-03T10:00",
                     "menu": "mie ayam", "total": Decimal("15000"), "status": "baru",
                     "topping": ["bakso", "pangsit"]})

item = tabel.get_item(Key={"pelanggan": "andi", "waktu": "2026-11-03T10:00"})["Item"]
print(item["menu"], item["topping"])

r = tabel.query(KeyConditionExpression=Key("pelanggan").eq("budi") & Key("waktu").begins_with("2026-11"))
print("total belanja budi di November:", sum(i["total"] for i in r["Items"]))

tabel.delete_item(Key={"pelanggan": "andi", "waktu": "2026-11-03T10:00"})
mie ayam ['bakso', 'pangsit']
total belanja budi di November: 50000

Angka DynamoDB dipetakan ke Decimal, bukan float. Memasukkan float langsung akan error.

Latihan mandiri

Latihan 1. Tampilkan pesanan terbaru Budi saja (satu item) dengan Query.
Lihat kunci jawaban 
aws dynamodb query --table-name Pesanan \
  --key-condition-expression "pelanggan = :p" \
  --expression-attribute-values '{":p": {"S": "budi"}}' \
  --no-scan-index-forward --limit 1 --query 'Items[0].menu.S'

Hasilnya "soto". Urut terbalik + limit 1 = item dengan sort key terbesar.

Latihan 2. Tambahkan pesanan baru untuk sari hanya jika item dengan key tersebut belum ada. Jalankan dua kali. Apa yang terjadi di percobaan kedua?
Lihat kunci jawaban 
aws dynamodb put-item --table-name Pesanan \
  --item '{"pelanggan": {"S": "sari"}, "waktu": {"S": "2026-11-05T07:00"}, "menu": {"S": "bubur"}}' \
  --condition-expression "attribute_not_exists(pelanggan)"

Percobaan pertama sukses. Percobaan kedua gagal dengan ConditionalCheckFailedException, sehingga item lama tidak tertimpa.

Latihan 3 (desain). Aplikasi chat perlu "ambil 50 pesan terakhir di sebuah ruang chat". Partition key dan sort key apa yang Anda pilih?
Lihat kunci jawaban

Partition key ruang_id, sort key waktu_kirim (ISO atau epoch). Query ruang_id = :r dengan --no-scan-index-forward --limit 50. Rancangan DynamoDB selalu dimulai dari pertanyaan yang akan sering diajukan.

Kuis

1. Operasi mana yang paling efisien untuk "semua pesanan pelanggan X"?
Query langsung menuju satu partisi. Scan membaca semua. GetItem butuh key lengkap.
2. Apa yang terjadi bila put-item memakai key yang sudah ada?
Untuk mengubah sebagian atribut, pakai update-item.
3. Kenapa waktu ditulis 2026-11-01T08:00, bukan 1/11/2026 8:00?
Sort key string diurutkan per karakter. Format ISO 8601 otomatis terurut secara kronologis.

Di AWS asli, apa bedanya?

  • On-demand (PAY_PER_REQUEST): bayar per baca/tulis. Provisioned: bayar kapasitas tetap, lebih murah untuk beban stabil.
  • Scan pada tabel besar bisa mahal karena dihitung per data yang dibaca, bukan yang dikembalikan.
  • Ada fitur lanjutan: GSI/LSI, TTL (hapus otomatis), Streams (memicu Lambda saat data berubah), transaksi.
