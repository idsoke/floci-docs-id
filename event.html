Alur Event Antar Layanan

Karena semua layanan berjalan di satu proses, Floci bisa menyambungkan mereka seperti di AWS: upload ke S3 memicu pesan SQS, SNS menyebar ke banyak antrean, EventBridge meneruskan event ke Lambda, dan seterusnya.

Penjelasan sederhana

Seperti rantai domino. Satu kejadian (file diunggah) menjatuhkan domino berikutnya (notifikasi dikirim), lalu domino berikutnya lagi (fungsi dijalankan). Di Floci, domino-domino ini benar-benar saling menyentuh, sehingga Anda bisa menguji seluruh alur aplikasi event-driven di laptop.

1. S3 → SQS → Lambda (pemrosesan unggahan)

aws s3api put-bucket-notification-configuration --bucket unggahan \
  --notification-configuration '{
    "QueueConfigurations": [{
      "QueueArn": "arn:aws:sqs:us-east-1:000000000000:proses-gambar",
      "Events": ["s3:ObjectCreated:*"]
    }]}'

PutBucketNotificationConfiguration memvalidasi ARN tujuan (SQS, SNS, Lambda). Unggahan lewat browser/presigned POST memicu s3:ObjectCreated:Post, bukan Put, sama seperti AWS. Gunakan s3:ObjectCreated:* untuk menangkap keduanya.

2. SNS fan-out

Protokol subscription yang didukung: sqs, lambda, firehose, http/https, application (mobile push tiruan). Filter policy (termasuk FilterPolicyScope=MessageBody) dievaluasi per subscription. Untuk SQS, pengiriman yang gagal dicoba hingga 3 kali; jika tetap gagal dan ada RedrivePolicy, pesan dikirim ke DLQ.

3. EventBridge: rule dan target

Target yang bisa dipakai antara lain Lambda, SQS, SNS, Step Functions, Kinesis, Firehose, event bus lain, API destination (HTTP), ECS task, dan Redshift Data API. Pola event dapat diuji tanpa memicu target dengan TestEventPattern. EventBridge Scheduler dan rule schedule (cron/rate) memicu target berdasarkan waktu.

4. Pola lain yang didukung

🌊 DynamoDB Streams → Lambda

Perubahan item ditulis ke stream. DynamoDbStreamsEventSourcePoller membaca shard dan memanggil fungsi dengan record INSERT/MODIFY/REMOVE.

📈 Kinesis → Lambda / Firehose

Record di stream Kinesis dibaca oleh poller ESM. Firehose dapat mengirim ke S3 dan tujuan lain.

🔧 EventBridge Pipes

Sumber (SQS, Kinesis, DynamoDB Streams) → filter → enrichment opsional → target. Poller Pipes dihidupkan kembali saat startup.

🪜 Step Functions

State machine (ASL) memanggil Lambda, SQS, SNS, DynamoDB, dan integrasi lain; mendukung activity dengan long-poll GetActivityTask.

📜 CloudWatch Logs

Log Lambda, ECS, dan konsol UI dialirkan ke log group. Subscription filter dan metric filter didukung.

🏗️ CloudFormation / CDK

Stack membuat resource di banyak layanan sekaligus melalui service yang sama, termasuk transform SAM.
