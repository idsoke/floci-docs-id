Konsep Dasar

Halaman ini menjelaskan ide di balik Floci tanpa istilah teknis yang berat. Cocok dibaca pertama kali.

1. Masalah yang diselesaikan

Aplikasi modern sering bergantung pada layanan AWS: file di S3, antrean pesan di SQS, database di DynamoDB, fungsi di Lambda. Saat pengembangan dan pengujian, memakai AWS asli punya beberapa masalah:

💸

Biaya

Setiap tes yang membuat bucket, tabel, atau memanggil Lambda bisa dikenai biaya. Kalau CI berjalan ratusan kali sehari, biayanya menumpuk.

🐢

Lambat & butuh internet

Setiap panggilan harus pergi ke server AWS dan kembali. Tanpa internet, tidak bisa kerja sama sekali.

🧹

Sisa sampah

Tes yang gagal di tengah jalan bisa meninggalkan resource yang lupa dihapus di akun.

🔑

Kredensial & izin

Developer baru perlu akun, akses, dan kunci. Kunci sungguhan bisa bocor.

Solusinya

Floci menjalankan tiruan AWS di komputer Anda. Aplikasi cukup diarahkan ke http://localhost:4566, dan semua panggilan dilayani secara lokal: gratis, cepat, offline, dan bisa dibuang kapan saja.

2. Apa itu "emulator"?

Emulator adalah program yang berperilaku seperti sistem lain. Floci tidak menyalin kode AWS (kode AWS tidak terbuka). Floci menulis ulang perilakunya berdasarkan spesifikasi publik: model layanan yang dipakai AWS SDK, dokumentasi API, dan pengamatan perilaku AWS asli.

Analogi: penerjemah dan formulir

Setiap layanan AWS punya "bahasa" (protokol) dan "formulir" (bentuk request/response) sendiri. SQS bicara dengan formulir Action=SendMessage&... dan dibalas XML. DynamoDB bicara JSON dengan header X-Amz-Target. S3 memakai alamat URL seperti /nama-bucket/nama-file.

Floci adalah petugas loket yang fasih semua bahasa itu. Ia membaca formulir apa pun yang Anda serahkan, mengerjakan permintaannya, lalu membalas dengan formulir yang persis sama seperti balasan AWS.

3. Prinsip terpenting: kompatibilitas wire protocol

"Wire protocol" artinya bentuk data yang benar-benar lewat di kabel jaringan: header HTTP, URL, isi JSON/XML, kode error. Floci tidak membuat API versi sendiri yang lebih praktis. Ia meniru bentuk aslinya byte demi byte sejauh mungkin. Karena itu SDK resmi (Java, Python boto3, Go, JavaScript, .NET), AWS CLI, Terraform, OpenTofu, dan CDK bisa langsung dipakai.

Dari AGENTS.md, urutan prioritas proyek ini adalah:

  1. Jaga kompatibilitas protokol AWS. Jangan membuat bentuk endpoint sendiri.
  2. Samakan perilaku dengan AWS SDK dan CLI. Termasuk pesan error dan kode HTTP.
  3. Pakai ulang pola Floci yang sudah ada. Salin pola layanan lain sebelum membuat pola baru.
  4. Utamakan kebenaran daripada kemudahan.
  5. Perubahan sempit dan bisa dites.

5. Tiga jenis "kedalaman" emulasi

Tidak semua layanan diemulasikan dengan cara yang sama. Secara garis besar ada tiga tingkat:

📝

Murni Java (in-process)

Logika ditulis ulang di Java dan state disimpan di Floci. Contoh: SQS, SNS, DynamoDB, IAM, SSM, KMS, Secrets Manager, Step Functions.

🐳

Container sungguhan

Floci menyalakan container Docker berisi perangkat lunak asli. Contoh: Lambda (runtime AWS), RDS (PostgreSQL/MySQL), ElastiCache (Redis), EKS (k3s), OpenSearch, Amazon MQ (RabbitMQ).

🎭

Metadata / tiruan respons

Beberapa layanan hanya menyimpan konfigurasi dan mengembalikan respons yang masuk akal, tanpa "mesin" sungguhan. Contoh: Pricing, Budgets, Cost Explorer, sebagian layanan AI.

6. Floci vs LocalStack

Floci dirancang sebagai pengganti langsung (drop-in replacement) LocalStack Community: port sama (4566), jalur init hooks LocalStack (/etc/localstack/init/...) tetap didukung, endpoint /_localstack/health dan /_localstack/init juga tersedia. Bedanya, Floci tidak memerlukan auth token dan tidak membatasi fitur di balik versi berbayar.
