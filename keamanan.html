Akun, IAM, Tanda Tangan & Partisi

Secara default Floci sangat longgar: kredensial apa pun diterima. Tapi di baliknya ada isolasi multi-akun, verifikasi tanda tangan opsional, penegakan kebijakan IAM opsional, dan dukungan semua partisi AWS.

Penjelasan sederhana

Default Floci itu seperti kos-kosan tanpa satpam: siapa pun boleh masuk, tapi setiap penghuni (akun) tetap punya kamar sendiri yang isinya tidak tercampur. Kalau Anda ingin latihan aturan keamanan yang ketat seperti di AWS sungguhan, Anda bisa memasang satpam (IAM enforcement) yang memeriksa kartu izin setiap tamu.

1. Menentukan akun dari access key

AccountContextFilter membaca Access Key ID (AKID) dari header Authorization, atau dari X-Amz-Credential untuk presigned URL, lalu menentukan akun dengan urutan:

Authorization: AWS4-HMAC-SHA256 Credential=111111111111/20261101/us-east-1/sqs/aws4_request, ...
                                            ^^^^^^^^^^^^ AKID 12 digit → account ID 111111111111

Aturan "AKID 12 digit = account ID" sama dengan LocalStack, jadi setup tes multi-akun yang sudah ada tetap jalan. Setelah akun diketahui, semua baca/tulis storage otomatis diberi namespace akun (lihat Penyimpanan Data).

# Dua akun, dua antrean bernama sama, tidak saling melihat
AWS_ACCESS_KEY_ID=111111111111 aws sqs create-queue --queue-name orders
AWS_ACCESS_KEY_ID=222222222222 aws sqs create-queue --queue-name orders
AWS_ACCESS_KEY_ID=111111111111 aws sqs list-queues   # hanya milik 1111...

2. Tiga tingkat keamanan

TingkatPengaturanPerilaku
🟢 Default(tidak ada)Kredensial apa pun yang tidak kosong diterima. Tanda tangan tidak diperiksa. Semua aksi diizinkan.
🟡 Verifikasi tanda tanganFLOCI_AUTH_VALIDATE_SIGNATURES=trueTanda tangan SigV4 setiap request bertanda tangan dihitung ulang (header, presigned URL, presigned POST). Kebijakan tidak dievaluasi.
🔴 IAM enforcementFLOCI_SERVICES_IAM_ENFORCEMENT_ENABLED=trueKredensial harus milik user IAM / sesi STS yang valid. Setiap request dievaluasi terhadap kebijakan sebelum mencapai service.

Banner startup menampilkan status efektif: IAM: policy enforcement enabled / disabled. Jika request yang seharusnya ditolak tetap lolos, periksa baris itu dulu.

3. Evaluasi kebijakan IAM (animasi)

Urutan evaluasi mengikuti aturan AWS standar:

  1. Jika SCP aktif, aksi harus diizinkan di setiap level organisasi (root, OU, akun) dan tidak ditolak di mana pun.
  2. Deny eksplisit di kebijakan identitas, sesi, atau boundary → ditolak.
  3. Allow eksplisit di kebijakan identitas → dasar izin.
  4. Jika ada session policy, ia juga harus mengizinkan.
  5. Jika ada permission boundary, ia juga harus mengizinkan.
  6. Tidak ada Allow efektif → implicit deny.
ProtokolRespons saat ditolak
JSON 1.0 / 1.1HTTP 400 AccessDeniedException
REST JSONHTTP 403 AccessDeniedException
Query, S3HTTP 403 XML AccessDenied
SNSHTTP 403 AuthorizationError

Floci membangun ARN resource sendiri untuk S3, Lambda, SQS, SNS, DynamoDB, Kinesis, SSM, KMS, IAM, Secrets Manager, STS, EventBridge Scheduler, Pipes, EKS, API Gateway, CloudWatch Logs, dan lainnya, sehingga statement dengan Resource spesifik bisa dievaluasi dengan benar. Resource policy (bucket policy, function policy Lambda, queue policy) juga ikut dievaluasi, termasuk akses lintas akun.

4. Partisi AWS

Partisi adalah segmen kedua setiap ARN (arn:aws-cn:...), sufiks DNS endpoint, dan daftar region/layanan yang tersedia di sana. Floci membaca semuanya dari metadata resmi botocore (partitions.json, endpoints.json).

PartisiSufiks DNSContoh region
awsamazonaws.comus-east-1, ap-southeast-3
aws-cnamazonaws.com.cncn-north-1
aws-us-govamazonaws.comus-gov-west-1
aws-iso, aws-iso-b, aws-iso-e, aws-iso-fberagamus-iso-east-1
aws-euscamazonaws.eueusc-de-east-1

Partisi deployment diturunkan dari FLOCI_DEFAULT_REGION (mis. cn-north-1 → aws-cn), atau dipaku dengan FLOCI_PARTITIONS_ID.

Untuk kontributor: literal "arn:aws:", amazonaws.com, atau perbandingan dengan "aws" di kode adalah bug di partisi lain. make partition-check (CI: Partition Literals) menggagalkan build jika ada literal baru. Gunakan AwsArnUtils.Arn.of(...), RegionResolver.buildArn(...), RegionResolver.buildGlobalArn, AwsRegions.dnsSuffixFor, dan ServicePrincipals.of("<service>").

5. Paparan jaringan & TLS

  • Floci menolak listen di luar loopback (127.0.0.1) kecuali FLOCI_SECURITY_ALLOW_UNSAFE_NETWORK_EXPOSURE=true (NetworkExposureGuard). Image Docker sudah men-set ini karena di dalam container ia listen di 0.0.0.0, jadi siapa yang bisa mengakses tergantung cara Anda mem-publish port.
  • Rekomendasi: docker run -p 127.0.0.1:4566:4566 floci/floci agar hanya bisa diakses dari mesin sendiri.
  • TLS opsional: FLOCI_TLS_ENABLED=true. HTTP dan HTTPS dilayani bersamaan di port yang sama. Floci punya CA lokal sendiri; unduh dari /_floci/ca.pem dan pakai AWS_CA_BUNDLE.
  • CORS browser bisa diatur dengan FLOCI_SECURITY_EXTRA_CORS_ALLOWED_ORIGINS dan variabel terkait.

Penting: Floci adalah alat pengembangan. Siapa pun yang bisa menjangkau port-nya bisa memanggil API-nya. Jangan mengekspos Floci ke internet.
