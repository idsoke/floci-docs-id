📨 Modul 2 · SQS: Antrean Pesan

⏱ 60–90 menit📶 Pemula🧩 Amazon SQS (Simple Queue Service)
Penjelasan sederhana

Bayangkan loket pesanan di restoran. Kasir (produser) menulis pesanan di kertas dan menancapkannya di papan. Koki (konsumen) mengambil satu kertas, memasak, lalu membuang kertasnya. Kasir tidak perlu menunggu koki selesai, dan kalau koki sedang sibuk, pesanan tetap aman menunggu di papan. Papan itulah antrean SQS.

Kalau koki pingsan saat memasak, kertasnya tidak hilang: setelah beberapa saat kertas itu kembali ke papan untuk diambil koki lain. Inilah visibility timeout, fitur terpenting SQS.

Tujuan modul

  • Membuat antrean, mengirim, menerima, dan menghapus pesan.
  • Memahami siklus hidup pesan: terlihat → tak terlihat → dihapus (atau kembali lagi).
  • Memakai long polling agar konsumen hemat request.
  • Membuat Dead-Letter Queue (DLQ) untuk pesan yang terus gagal.

Konsep kunci

IstilahArti
Queue URLAlamat antrean, dipakai di hampir semua perintah: http://localhost:4566/000000000000/pesanan
Message bodyIsi pesan berupa teks (sering JSON), maksimal 256 KB
Receipt handle"Tiket" yang Anda dapat saat menerima pesan. Dibutuhkan untuk menghapus pesan. Berubah setiap kali diterima.
Visibility timeoutLama pesan disembunyikan setelah diterima (default 30 detik). Jika tidak dihapus dalam waktu itu, pesan muncul lagi.
Long pollingKonsumen menunggu hingga 20 detik sampai ada pesan, daripada bertanya terus-menerus
DLQAntrean "gudang pesan bermasalah". Pesan pindah ke sini setelah diterima lebih dari maxReceiveCount kali tanpa dihapus.
Standard vs FIFOStandard: sangat cepat, urutan tidak dijamin, bisa terkirim dua kali. FIFO (.fifo): urutan dijamin, tepat sekali.

Animasi: siklus hidup sebuah pesan

Langkah praktik

Buat antrean

aws sqs create-queue --queue-name pesanan
aws sqs list-queues

# simpan URL-nya ke variabel agar perintah berikutnya pendek
Q=$(aws sqs get-queue-url --queue-name pesanan --query QueueUrl --output text)
echo $Q
{
    "QueueUrl": "http://localhost:4566/000000000000/pesanan"
}
...
http://localhost:4566/000000000000/pesanan

Opsi --query memakai bahasa JMESPath untuk mengambil satu nilai dari JSON, dan --output text menghilangkan tanda kutip. Kombinasi ini akan sering Anda pakai.

Kirim pesan

aws sqs send-message --queue-url $Q --message-body '{"id": 1, "menu": "nasi goreng"}'
aws sqs send-message --queue-url $Q --message-body '{"id": 2, "menu": "soto ayam"}'

aws sqs get-queue-attributes --queue-url $Q --attribute-names ApproximateNumberOfMessages
{
    "MD5OfMessageBody": "…",
    "MessageId": "6f1c…"
}
...
{
    "Attributes": {
        "ApproximateNumberOfMessages": "2"
    }
}

Terima pesan

aws sqs receive-message --queue-url $Q
{
    "Messages": [
        {
            "MessageId": "6f1c…",
            "ReceiptHandle": "AQEB…panjang…",
            "MD5OfBody": "…",
            "Body": "{\"id\": 1, \"menu\": \"nasi goreng\"}"
        }
    ]
}

Default-nya satu pesan per panggilan. Pakai --max-number-of-messages 10 untuk mengambil hingga 10 sekaligus. Pada antrean standard, urutan pesan tidak dijamin.

Eksperimen visibility timeout

Ini eksperimen terpenting di modul ini. Kita terima pesan dengan timeout 10 detik, tanpa menghapusnya.

aws sqs receive-message --queue-url $Q --visibility-timeout 10 --max-number-of-messages 10 \
  --query 'Messages[].Body'
aws sqs receive-message --queue-url $Q --query 'Messages[].Body'     # langsung lagi: kosong
sleep 11
aws sqs receive-message --queue-url $Q --query 'Messages[].Body'     # pesan muncul lagi!
[
    "{\"id\": 1, \"menu\": \"nasi goreng\"}",
    "{\"id\": 2, \"menu\": \"soto ayam\"}"
]
null
[
    "{\"id\": 1, \"menu\": \"nasi goreng\"}"
]

Pesan tidak dihapus oleh receive. Ia hanya disembunyikan. Kalau konsumen crash sebelum menghapus, pesan kembali ke antrean sehingga tidak ada pesanan yang hilang.

Hapus pesan setelah diproses

RH=$(aws sqs receive-message --queue-url $Q --visibility-timeout 30 \
      --query 'Messages[0].ReceiptHandle' --output text)
aws sqs delete-message --queue-url $Q --receipt-handle "$RH"

aws sqs purge-queue --queue-url $Q      # kosongkan semua pesan sekaligus
import boto3, json
sqs = boto3.client("sqs")
q = sqs.get_queue_url(QueueName="pesanan")["QueueUrl"]

for i in range(3):
    sqs.send_message(QueueUrl=q, MessageBody=json.dumps({"id": i, "menu": f"menu-{i}"}))

while True:
    r = sqs.receive_message(QueueUrl=q, MaxNumberOfMessages=10, WaitTimeSeconds=5)
    msgs = r.get("Messages", [])
    if not msgs:
        print("antrean kosong, selesai")
        break
    for m in msgs:
        pesanan = json.loads(m["Body"])
        print("memasak", pesanan["menu"])
        sqs.delete_message(QueueUrl=q, ReceiptHandle=m["ReceiptHandle"])  # wajib!

delete-message tidak mencetak apa pun jika sukses. Pola baku konsumen: terima → proses → hapus.

Long polling

Buka dua terminal (keduanya dengan variabel dari Modul 0 dan $Q).

# Terminal 1: menunggu hingga 20 detik
time aws sqs receive-message --queue-url $Q --wait-time-seconds 20 --query 'Messages[].Body'

# Terminal 2: kirim dalam beberapa detik
aws sqs send-message --queue-url $Q --message-body "pesan kilat"
[
    "pesan kilat"
]
real    0m3.2s

Terminal 1 langsung menjawab begitu pesan datang, tidak perlu menunggu 20 detik penuh. Di AWS asli, long polling menghemat biaya karena jumlah request kosong jauh berkurang.

Dead-Letter Queue

aws sqs create-queue --queue-name pesanan-gagal
DLQ_ARN=$(aws sqs get-queue-attributes \
  --queue-url http://localhost:4566/000000000000/pesanan-gagal \
  --attribute-names QueueArn --query Attributes.QueueArn --output text)

aws sqs create-queue --queue-name pesanan-v2 --attributes "{
  \"VisibilityTimeout\": \"1\",
  \"RedrivePolicy\": \"{\\\"deadLetterTargetArn\\\":\\\"$DLQ_ARN\\\",\\\"maxReceiveCount\\\":\\\"2\\\"}\"
}"
Q2=http://localhost:4566/000000000000/pesanan-v2

aws sqs send-message --queue-url $Q2 --message-body "pesanan beracun"
for i in 1 2 3; do aws sqs receive-message --queue-url $Q2 --query 'Messages[].Body'; sleep 2; done

aws sqs receive-message --queue-url http://localhost:4566/000000000000/pesanan-gagal --query 'Messages[].Body'
[
    "pesanan beracun"
]
[
    "pesanan beracun"
]
null
[
    "pesanan beracun"
]

Pesan diterima 2 kali tanpa dihapus (anggap konsumen selalu gagal). Pada percobaan ke-3, SQS memindahkannya ke pesanan-gagal. Tanpa DLQ, pesan "beracun" seperti ini akan berputar selamanya.

Tanda kutip berlapis memang merepotkan: RedrivePolicy adalah string JSON di dalam JSON. Di Python jauh lebih mudah: Attributes={"RedrivePolicy": json.dumps({"deadLetterTargetArn": arn, "maxReceiveCount": "2"})}.

Kesalahan umum

GejalaPenyebab
Pesan diproses berkali-kaliLupa delete-message, atau proses lebih lama daripada visibility timeout
AWS.SimpleQueueService.NonExistentQueueQueue URL salah, atau Floci sudah di-reset
ReceiptHandleIsInvalidReceipt handle salah salin atau berasal dari penerimaan lama
QueueDeletedRecentlyMembuat ulang antrean dengan nama yang baru saja dihapus. Tunggu sebentar (di AWS asli 60 detik).
Receive selalu nullSemua pesan sedang "in flight" (tak terlihat). Cek ApproximateNumberOfMessagesNotVisible.

Latihan mandiri

Latihan 1. Kirim 5 pesan, terima 3 tanpa menghapus. Tampilkan jumlah pesan terlihat dan tidak terlihat.
Lihat kunci jawaban 
for i in 1 2 3 4 5; do aws sqs send-message --queue-url $Q --message-body "m$i" >/dev/null; done
aws sqs receive-message --queue-url $Q --max-number-of-messages 3 >/dev/null
aws sqs get-queue-attributes --queue-url $Q \
  --attribute-names ApproximateNumberOfMessages ApproximateNumberOfMessagesNotVisible

Hasilnya kira-kira 2 terlihat dan 3 tidak terlihat. Receive bisa mengembalikan kurang dari 3 pesan, jadi angkanya bisa sedikit berbeda.

Latihan 2. Buat antrean FIFO urut.fifo, kirim pesan A, B, C dengan --message-group-id yang sama, lalu terima. Apakah urutannya terjaga?
Lihat kunci jawaban 
aws sqs create-queue --queue-name urut.fifo --attributes FifoQueue=true,ContentBasedDeduplication=true
F=http://localhost:4566/000000000000/urut.fifo
for m in A B C; do aws sqs send-message --queue-url $F --message-body $m --message-group-id g1 >/dev/null; done
aws sqs receive-message --queue-url $F --max-number-of-messages 10 --query 'Messages[].Body'

Hasilnya ["A","B","C"]. Dalam satu message group, FIFO menjamin urutan. ContentBasedDeduplication membuat pesan dengan isi sama dalam 5 menit dianggap duplikat.

Kuis

1. Konsumen menerima pesan lalu crash sebelum menghapusnya. Apa yang terjadi?
Itulah gunanya visibility timeout: menjamin pesan tidak hilang ketika pemroses gagal.
2. Apa yang dibutuhkan untuk menghapus pesan?
Receipt handle membuktikan Anda yang sedang memegang pesan itu.
3. Kenapa SQS dipakai di antara dua bagian aplikasi?
SQS memisahkan (decouple) sistem. Untuk menyiarkan ke banyak penerima, pakai SNS (Modul 3). Pesan SQS default disimpan 4 hari, bukan permanen.

Di AWS asli, apa bedanya?

  • Queue URL berbentuk https://sqs.us-east-1.amazonaws.com/123456789012/pesanan.
  • Biaya per juta request. Long polling dan batch (hingga 10 pesan) membuatnya jauh lebih murah.
  • Pesan disimpan default 4 hari, maksimal 14 hari.
