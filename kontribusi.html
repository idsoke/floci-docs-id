Panduan Kontributor

Ringkasan CONTRIBUTING.md dan AGENTS.md: menyiapkan lingkungan, build, tes, gaya kode, format commit, dan langkah-langkah menambah layanan atau resource CloudFormation.

Penjelasan sederhana

Berkontribusi ke Floci itu seperti menambah loket baru di kantor pelayanan. Ada SOP yang jelas: daftarkan loketnya di buku induk (ResolvedServiceCatalog), sediakan petugas (controller) dan staf ahli (service), siapkan lemari arsip (storage), buat uji coba (tes), lalu tulis papan petunjuknya (dokumentasi). Kalau satu langkah terlewat, CI biasanya akan menegur.

Prasyarat

  • Java 25+ (mis. lewat SDKMAN: sdk install java 25-open)
  • Maven 3.9+ atau pakai wrapper ./mvnw
  • Docker untuk tes integrasi Lambda/RDS/ElastiCache

Format commit & judul PR

Floci memakai Conventional Commits. Judul PR divalidasi CI karena menjadi pesan squash-merge yang dibaca semantic-release.

<type>[(scope)]: <deskripsi singkat, mode perintah, tanpa titik>
TypeKapanVersi
featAction atau layanan AWS baruminor
fixPerbaikan bug / kompatibilitas AWSpatch
perfPeningkatan performapatch
docs, test, refactor, chore, build, ci, styleTanpa perubahan perilaku—
feat! / footer BREAKING CHANGEPerubahan tidak kompatibelmajor
✅ fix(s3): make us-east-1 bucket creation idempotent
✅ feat(dynamodb): add PartiQL ExecuteStatement support
❌ Add PartiQL support          (tidak ada type)
❌ FIX(s3): ...                 (type harus huruf kecil)

Penting: jangan menambahkan trailer Co-Authored-By untuk alat AI di commit. CI (cek PR hygiene → Commits omit AI attribution trailers) akan menggagalkan PR tersebut. Atribusi hanya untuk kontributor manusia.

Gaya kode

  • Lolos Checkstyle.
  • Tipe eksplisit, jangan pakai var (kecuali record deconstruction pattern).
  • Import kelas; jangan nama lengkap inline. Tanpa wildcard import di src/main.
  • Urutan import: non-JDK (alfabetis), javax, java, static.
  • Jangan ada catch kosong; jika memang diabaikan, beri nama ignored/expected dan komentar alasannya.
  • Selalu pakai kurung kurawal di kondisional; gunakan constructor injection.
  • Nama tes: kalimat camelCase atau method_scenario_expectation, bukan testX.
  • Konvensi tes: unit = *ServiceTest.java, integrasi = *IntegrationTest.java.

Menambah layanan AWS baru (13 langkah)

  1. Buat paket services/<svc>/ berisi Controller/handler sesuai protokol, Service, dan model/.
  2. Tambah antarmuka <Svc>ServiceConfig dan aksesornya di ServicesConfig dalam EmulatorConfig.
  3. Tambah satu descriptor(...) di ResolvedServiceCatalog. Ini satu-satunya titik registrasi.
  4. Tambah floci.services.<key>.enabled di application.yml utama dan tes.
  5. Khusus JSON 1.1: suntikkan <Svc>JsonHandler ke AwsJson11Controller dan tambah case.
  6. Ambil storage lewat StorageFactory dan implementasikan Resettable.
  7. Daftarkan field static Random/SecureRandom di --initialize-at-run-time (untuk native image).
  8. Periksa TimestampFormatTrait setiap member timestamp (lihat dengan javap -c pada kelas model SDK).
  9. Tambah <Svc>ServiceTest dan <Svc>IntegrationTest.
  10. Jika membuat ARN/host: tambah kasus di PartitionCrossServiceSmokeIntegrationTest atau baris pengecualian di smoke-exemptions.tsv.
  11. Dokumentasi: docs/services/<svc>.md, nav mkdocs.yml, baris Service Matrix, baris tabel README.
  12. Daftarkan handler di tools/docs/services.yaml, lalu make docs-sync dan make docs-check.
  13. Tambah factory di TestFixtures dan <Svc>Test di compatibility-tests/sdk-test-java.

Menambah resource type CloudFormation

  1. Buat/ubah services/cloudformation/provisioners/<Service>CfnProvisioner.java dengan @ApplicationScoped (registrasi otomatis lewat CDI).
  2. Implementasikan resourceTypes() dan provision(...); set physical ID (untuk Ref) dan map atribut (untuk Fn::GetAtt).
  3. provision juga jalur update: gunakan ctx.isUpdate() dan ctx.priorPhysicalId().
  4. Override delete(...); toleransi "sudah terhapus" dengan CfnDeletes.safeDelete dan kode error spesifik.
  5. Daftarkan di src/test/resources/cloudformation/supported-resource-types.tsv.
  6. Buat dapat dijangkau dari CfnProvisionerFixture (field, setter, arm konstruksi).
  7. Tes: assert kunci atribut Fn::GetAtt spesifik, bukan hanya CREATE_COMPLETE.
  8. make docs-sync; jangan edit tabel resource type secara manual.

Checklist sebelum membuka PR

  • ☐ Perilaku sama dengan AWS (cek dokumentasi API dan model SDK)
  • ☐ Tes unit + integrasi; tes SDK jika menyentuh protokol
  • ☐ Jalur protokol alternatif (Query/JSON/CBOR) tetap konsisten
  • ☐ ./mvnw checkstyle:check dan make partition-check lolos
  • ☐ Dokumentasi diperbarui, make docs-check lolos
  • ☐ Judul PR mengikuti Conventional Commits, tanpa trailer atribusi AI
  • ☐ Perubahan sempit; tidak ada refactor yang tidak diminta
