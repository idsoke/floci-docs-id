Protokol AWS (Wire Protocol)

AWS tidak memakai satu format API saja. Ada lima keluarga protokol, dan Floci harus fasih semuanya supaya SDK resmi bisa dipakai tanpa diubah.

Penjelasan sederhana

Anggap protokol sebagai jenis formulir. Ada kantor yang meminta formulir isian kotak-kotak (Query), ada yang meminta surat berformat JSON dengan perihal di amplop (JSON 1.1), ada yang memakai alamat rumah sebagai petunjuk (REST). Floci punya petugas yang bisa melihat amplop dari luar dan langsung tahu formulir jenis apa di dalamnya, tanpa perlu membukanya.

Animasi: bagaimana Floci mengenali protokol

ProtocolClaimer mengikuti panduan Smithy wire-protocol selection. Ia hanya membaca sinyal di luar body (method, path, header, query) sehingga aman dijalankan di filter pre-matching tanpa menyentuh isi request.

Urutan presisi pemeriksaan

  1. Smithy-Protocol header ada? Jika ya, ini sinyal eksklusif rpcv2. Harus POST dan path cocok .../service/{S}/operation/{O}. Nilai tidak dikenal → tidak bisa diklaim (tidak jatuh ke protokol lain).
  2. rpcv2 CBOR (application/cbor) lalu rpcv2 JSON.
  3. awsJson1_0: application/x-amz-json-1.0 + X-Amz-Target.
  4. awsJson1_1: application/x-amz-json-1.1 + X-Amz-Target.
  5. awsQuery: POST / dengan form-encoded, atau GET Query bertanda tangan (ditulis ulang ke path GET Query internal).
  6. REST: selain itu. Layanan ditentukan dari route JAX-RS yang cocok.

Mode strict: request yang membawa sinyal RPC tapi tidak bisa diklaim akan dicatat di log. Dengan floci.protocols.strict-claiming=true, request itu ditolak 404 UnknownOperationException. Tanpa mode strict, AwsRouteClaimFilter mengklaimnya berdasarkan route yang tercapai.

Cara Query menentukan layanan

Banyak layanan Query sama-sama memakai POST / dengan form. AwsQueryController membedakannya dengan:

  1. Scope kredensial SigV4: Credential=.../us-east-1/sns/aws4_request → layanan SNS.
  2. Jika tidak ada header atau scope-nya bukan layanan Query: dari nama Action dan Version yang dideklarasikan (inferServiceFromAction).

Satu layanan, beberapa protokol

Beberapa layanan menerima lebih dari satu protokol. Contoh dari ResolvedServiceCatalog:

descriptor("sqs", "sqs", config.services().sqs().enabled(), true,
        "sqs", storageMode(...),
        5000L, AwsNamespaces.SQS, ServiceProtocol.QUERY,               // protokol default
        protocols(ServiceProtocol.QUERY, ServiceProtocol.JSON, ServiceProtocol.CBOR),
        Set.of("AmazonSQS."),   // prefix X-Amz-Target
        Set.of("sqs"),          // nama signing SigV4
        Set.of("SQS"), Set.of())

Aturan proyek: jalur alternatif ini tidak boleh "melenceng". Kalau Anda memperbaiki perilaku SQS di jalur Query, jalur JSON dan CBOR harus menghasilkan hasil yang sama. Begitu juga CloudWatch Metrics (Query + JSON 1.1).

Aturan format yang wajib diikuti kontributor

  • XML dibuat dengan XmlBuilder dan dibaca dengan XmlParser. Jangan pakai regex.
  • Namespace XML diambil dari konstanta AwsNamespaces.
  • Timestamp JSON: periksa TimestampFormatTrait di model SDK. Default awsJson1.1 adalah epoch-seconds, tapi model bisa menimpanya per member. AWS CLI tidak peduli, tapi SDK Go/Java akan menolak seluruh respons jika formatnya salah.
  • Error JSON harus mengikuti struktur {"__type": ..., "message": ...}.
  • Jangan pernah membuat bentuk endpoint kustom atau mengubah format demi kemudahan.
