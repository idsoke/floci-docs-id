🏁 Modul 7 · Proyek Akhir: Pemroses Pesanan

⏱ 2–3 jam📶 Menengah🧩 S3 · SQS · Lambda · DynamoDB · SNS
Penjelasan sederhana

Kita membangun "dapur otomatis" sebuah warung online. Pelanggan menaruh file pesanan di S3. S3 menaruh catatan di antrean SQS. Lambda mengambil catatan itu, membaca file pesanan, mencatatnya di DynamoDB, lalu mengumumkan lewat SNS bahwa pesanan sudah diproses. Bagian notifikasi menerima pengumuman di antreannya sendiri.

Inilah pola event-driven serverless yang sangat umum di AWS: tidak ada server yang menyala terus, setiap bagian bergerak hanya karena ada event.

Langkah praktik

Sebelum mulai: Floci berjalan tanpa penegakan IAM dan dengan docker.sock (lihat langkah terakhir Modul 6). Kerjakan di satu folder baru: mkdir ~/proyek-pesanan && cd ~/proyek-pesanan.

Buat semua resource dengan satu skrip

cat > infra.sh <<'EOF'
#!/usr/bin/env bash
set -euo pipefail
B=http://localhost:4566/000000000000
arn_q() { aws sqs get-queue-attributes --queue-url $B/$1 --attribute-names QueueArn --query Attributes.QueueArn --output text; }

aws s3 mb s3://pesanan-masuk

aws dynamodb create-table --table-name PesananTercatat \
  --attribute-definitions AttributeName=pelanggan,AttributeType=S AttributeName=id,AttributeType=S \
  --key-schema AttributeName=pelanggan,KeyType=HASH AttributeName=id,KeyType=RANGE \
  --billing-mode PAY_PER_REQUEST >/dev/null

aws sqs create-queue --queue-name pesanan-rusak >/dev/null
aws sqs create-queue --queue-name antrean-pesanan --attributes "{
  \"VisibilityTimeout\": \"30\",
  \"RedrivePolicy\": \"{\\\"deadLetterTargetArn\\\":\\\"$(arn_q pesanan-rusak)\\\",\\\"maxReceiveCount\\\":\\\"3\\\"}\"
}" >/dev/null

TOPIC=$(aws sns create-topic --name pesanan-diproses --query TopicArn --output text)
aws sqs create-queue --queue-name notifikasi >/dev/null
aws sns subscribe --topic-arn $TOPIC --protocol sqs --notification-endpoint $(arn_q notifikasi) \
  --attributes RawMessageDelivery=true >/dev/null

echo "TOPIC=$TOPIC"
echo "QUEUE_ARN=$(arn_q antrean-pesanan)"
EOF
chmod +x infra.sh && ./infra.sh
make_bucket: pesanan-masuk
TOPIC=arn:aws:sns:us-east-1:000000000000:pesanan-diproses
QUEUE_ARN=arn:aws:sqs:us-east-1:000000000000:antrean-pesanan

set -euo pipefail membuat skrip berhenti di error pertama. Membuat infrastruktur lewat skrip (bukan klik-klik) adalah awal dari Infrastructure as Code. Langkah berikutnya adalah Terraform atau CloudFormation, yang keduanya didukung Floci.

Sambungkan S3 → SQS

B=http://localhost:4566/000000000000
aws s3api put-bucket-notification-configuration --bucket pesanan-masuk \
  --notification-configuration '{
    "QueueConfigurations": [{
      "QueueArn": "arn:aws:sqs:us-east-1:000000000000:antrean-pesanan",
      "Events": ["s3:ObjectCreated:*"],
      "Filter": {"Key": {"FilterRules": [{"Name": "suffix", "Value": ".json"}]}}
    }]
  }'

aws sqs receive-message --queue-url $B/antrean-pesanan --query 'Messages[0].Body' --output text
{"Service":"Amazon S3","Event":"s3:TestEvent","Time":"…","Bucket":"pesanan-masuk",…}

Saat konfigurasi diterima, S3 mengirim pesan uji s3:TestEvent. Pesan ini tidak punya Records, jadi kode Lambda kita harus mengabaikannya. Filter suffix .json berarti hanya file berakhiran .json yang memicu event.

Tulis kode Lambda

cat > proses.py <<'EOF'
import json, os, urllib.parse
from decimal import Decimal
import boto3
from botocore.config import Config

# Floci menyuntikkan AWS_ENDPOINT_URL ke container Lambda, jadi boto3 otomatis bicara ke Floci.
# path-style agar nama bucket tidak perlu di-resolve sebagai hostname dari dalam container.
s3 = boto3.client("s3", config=Config(s3={"addressing_style": "path"}))
tabel = boto3.resource("dynamodb").Table(os.environ["TABLE"])
sns = boto3.client("sns")
WAJIB = ("id", "pelanggan", "items")

def proses_satu(bucket, key):
    isi = s3.get_object(Bucket=bucket, Key=key)["Body"].read()
    p = json.loads(isi, parse_float=Decimal)              # error di sini = file rusak
    hilang = [f for f in WAJIB if f not in p]
    if hilang:
        raise ValueError(f"{key}: field wajib hilang {hilang}")
    total = sum(Decimal(i["harga"]) * i["jumlah"] for i in p["items"])
    tabel.put_item(Item={**p, "id": str(p["id"]), "total": total, "status": "diproses", "sumber": key})
    sns.publish(TopicArn=os.environ["TOPIC_ARN"],
                Message=json.dumps({"id": str(p["id"]), "pelanggan": p["pelanggan"], "total": str(total)}),
                MessageAttributes={"pelanggan": {"DataType": "String", "StringValue": p["pelanggan"]}})
    print(f"OK pesanan {p['id']} milik {p['pelanggan']}: total {total}")

def handler(event, context):
    for rec in event["Records"]:                          # setiap rec = satu pesan SQS
        body = json.loads(rec["body"])
        if body.get("Event") == "s3:TestEvent":
            print("abaikan pesan uji S3")
            continue
        for s3rec in body.get("Records", []):             # setiap s3rec = satu event S3
            bucket = s3rec["s3"]["bucket"]["name"]
            key = urllib.parse.unquote_plus(s3rec["s3"]["object"]["key"])
            proses_satu(bucket, key)
EOF
zip -q proses.zip proses.py

Perhatikan dua lapis: SQS membungkus event S3. Satu pesan SQS bisa berisi satu atau lebih record S3. unquote_plus diperlukan karena key di event S3 di-encode (spasi menjadi +).

Deploy Lambda dan sambungkan ke SQS

TOPIC=arn:aws:sns:us-east-1:000000000000:pesanan-diproses

aws lambda create-function --function-name proses-pesanan \
  --runtime python3.12 --handler proses.handler \
  --role arn:aws:iam::000000000000:role/lambda-role \
  --zip-file fileb://proses.zip --timeout 30 \
  --environment "Variables={TABLE=PesananTercatat,TOPIC_ARN=$TOPIC}" \
  --query State

aws lambda create-event-source-mapping --function-name proses-pesanan \
  --event-source-arn arn:aws:sqs:us-east-1:000000000000:antrean-pesanan \
  --batch-size 5 --query State

Bersih-bersih

cat > hapus.sh <<'EOF'
#!/usr/bin/env bash
B=http://localhost:4566/000000000000
for u in $(aws lambda list-event-source-mappings --function-name proses-pesanan --query 'EventSourceMappings[].UUID' --output text); do
  aws lambda delete-event-source-mapping --uuid $u >/dev/null; done
aws lambda delete-function --function-name proses-pesanan
aws s3 rb s3://pesanan-masuk --force
aws dynamodb delete-table --table-name PesananTercatat >/dev/null
for q in antrean-pesanan pesanan-rusak notifikasi; do aws sqs delete-queue --queue-url $B/$q; done
aws sns delete-topic --topic-arn arn:aws:sns:us-east-1:000000000000:pesanan-diproses
echo "bersih"
EOF
chmod +x hapus.sh && ./hapus.sh

Di Floci Anda juga bisa langsung docker rm -f floci. Di AWS asli, skrip pembersih seperti ini menyelamatkan dompet: resource yang lupa dihapus akan terus ditagih.

Tantangan lanjutan

🔐

Least privilege

Nyalakan penegakan IAM, buat role proses-pesanan-role yang hanya boleh s3:GetObject pada bucket ini, dynamodb:PutItem pada tabel ini, dan sns:Publish pada topic ini. Pakai sebagai --role.

🌐

API HTTP

Tambahkan API Gateway + Lambda GET /pesanan/{pelanggan} yang melakukan Query ke DynamoDB.

🧱

Infrastructure as Code

Tulis ulang infra.sh sebagai Terraform (lihat halaman Cara Memakai) lalu terraform apply ke Floci.

🎯

Filter notifikasi

Tambahkan antrean notifikasi-vip dengan filter policy yang hanya menerima pesanan bertotal di atas 50.000 (petunjuk: filter numerik {"numeric": [">", 50000]}, kirim total sebagai atribut Number).

🧪

Tes otomatis

Tulis tes pytest yang menjalankan infra.sh, mengunggah pesanan, lalu menunggu sampai item muncul di DynamoDB.

☁️

Coba di AWS asli

Dengan budget alert aktif, jalankan skrip yang sama di akun AWS sungguhan (hapus AWS_ENDPOINT_URL). Catat perbedaan yang muncul, misalnya izin queue policy untuk S3 dan SNS.

Kuis akhir

1. Kenapa ada SQS di antara S3 dan Lambda, padahal S3 bisa langsung memanggil Lambda?
S3 → Lambda langsung memang bisa, tetapi antrean memberi kontrol atas retry, batch, dan DLQ.
2. Kalau DynamoDB sedang error, apa yang terjadi pada pesanan yang masuk?
Inilah ketahanan (resilience) yang didapat dari pola antrean.
3. Layanan notifikasi ingin ikut tahu tanpa mengubah kode Lambda. Caranya?
Fan-out SNS membuat penerima baru bisa ditambah tanpa menyentuh pengirim.
