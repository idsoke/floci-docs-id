λ Modul 5 · Lambda: Kode Tanpa Server

⏱ 90 menit📶 Menengah🧩 AWS Lambda + CloudWatch Logs
Penjelasan sederhana

Biasanya untuk menjalankan program Anda menyewa server yang menyala 24 jam, meski sering menganggur. Lambda seperti tukang panggilan: Anda menitipkan "resep kerja" (kode), dan tukang itu baru datang ketika dipanggil (ada event), bekerja beberapa detik, lalu pergi. Anda hanya membayar selama ia bekerja.

Di Floci, setiap "tukang" adalah container Docker yang memakai image runtime resmi AWS. Karena itu Floci harus dijalankan dengan akses ke docker.sock (lihat Modul 0).

Tujuan modul

  • Menulis handler Python, mengemas, dan men-deploy fungsi.
  • Memanggil (invoke) fungsi dan membaca log-nya.
  • Memakai environment variable dan memperbarui kode.
  • Memahami error fungsi, cold start, dan warm start.
  • Membuat fungsi otomatis berjalan setiap ada pesan SQS (event source mapping).

Konsep kunci

IstilahArti
HandlerFungsi yang dipanggil Lambda: def handler(event, context). Ditulis sebagai namafile.namafungsi, mis. app.handler.
EventData masukan (JSON). Isinya tergantung pemicunya: payload manual, pesan SQS, notifikasi S3, …
RuntimeBahasa + versi: python3.12, nodejs22.x, java21, …
Execution roleRole IAM yang izinnya dipakai kode fungsi saat memanggil layanan lain
Cold / warm startCold: container harus dibuat dulu (lambat). Warm: container lama dipakai ulang (cepat).
TimeoutBatas waktu eksekusi (default 3 detik, maksimal 15 menit)
Event source mappingLambda sendiri yang menarik pesan dari SQS/Kinesis/DynamoDB Streams lalu memanggil fungsi

Langkah praktik

Cek dulu: Floci harus berjalan dengan -v /var/run/docker.sock:/var/run/docker.sock -u root. Invoke pertama akan mengunduh image public.ecr.aws/lambda/python:3.12 (±200 MB), jadi tunggu beberapa saat.

Tulis kode dan kemas jadi ZIP

mkdir -p fungsi-halo && cd fungsi-halo
cat > app.py <<'EOF'
import json, os

def handler(event, context):
    nama = event.get("nama", "teman")
    sapaan = os.environ.get("SAPAAN", "Halo")
    print(f"menerima event: {json.dumps(event)}")      # masuk ke CloudWatch Logs
    return {"pesan": f"{sapaan}, {nama}!", "sisa_waktu_ms": context.get_remaining_time_in_millis()}
EOF

zip fungsi.zip app.py                       # atau: python3 -m zipfile -c fungsi.zip app.py
  adding: app.py (deflated 30%)

Deploy fungsi

aws lambda create-function \
  --function-name halo \
  --runtime python3.12 \
  --handler app.handler \
  --role arn:aws:iam::000000000000:role/lambda-role \
  --zip-file fileb://fungsi.zip \
  --timeout 10 \
  --query '{nama: FunctionName, state: State, runtime: Runtime}'
{
    "nama": "halo",
    "state": "Active",
    "runtime": "python3.12"
}

fileb:// artinya "baca file ini sebagai biner". Di AWS asli role lambda-role harus benar-benar ada; Floci menerima ARN role apa pun selama formatnya benar. Di AWS asli status awalnya bisa Pending: pakai aws lambda wait function-active-v2 --function-name halo.

Panggil fungsi (invoke)

time aws lambda invoke --function-name halo \
  --cli-binary-format raw-in-base64-out \
  --payload '{"nama": "Idris"}' hasil.json
cat hasil.json; echo

time aws lambda invoke --function-name halo \
  --cli-binary-format raw-in-base64-out \
  --payload '{"nama": "Sari"}' hasil.json      # kedua kali: jauh lebih cepat

--cli-binary-format raw-in-base64-out wajib di CLI v2 agar payload JSON tidak dianggap base64. Nama container persisnya bisa berbeda.

Baca log

print() di fungsi masuk ke CloudWatch Logs, grup /aws/lambda/halo.

# Cara 1: ambil 4 KB log terakhir langsung dari invoke
aws lambda invoke --function-name halo --cli-binary-format raw-in-base64-out \
  --payload '{"nama": "Log"}' --log-type Tail --query LogResult --output text hasil.json | base64 -d

# Cara 2: baca dari CloudWatch Logs
aws logs tail /aws/lambda/halo --since 10m

Saat fungsi error

aws lambda invoke --function-name halo --cli-binary-format raw-in-base64-out \
  --payload '"bukan objek"' hasil.json
cat hasil.json; echo
{
    "StatusCode": 200,
    "FunctionError": "Unhandled",
    "ExecutedVersion": "$LATEST"
}
{"errorMessage": "'str' object has no attribute 'get'", "errorType": "AttributeError", "stackTrace": [ … ]}

Perhatikan: StatusCode tetap 200, karena pemanggilannya berhasil walau kode Anda gagal. Tanda error-nya ada di FunctionError. Ini sering mengecoh pemula: selalu periksa FunctionError.

Dipicu otomatis oleh SQS

cat > pekerja.py <<'EOF'
import json

def handler(event, context):
    for rec in event["Records"]:
        pesanan = json.loads(rec["body"])
        print(f"memproses pesanan #{pesanan['id']}: {pesanan['menu']}")
    return {"diproses": len(event["Records"])}
EOF
zip -q pekerja.zip pekerja.py

aws lambda create-function --function-name pekerja --runtime python3.12 \
  --handler pekerja.handler --role arn:aws:iam::000000000000:role/lambda-role \
  --zip-file fileb://pekerja.zip --query State

aws sqs create-queue --queue-name tugas >/dev/null
QARN=$(aws sqs get-queue-attributes --queue-url http://localhost:4566/000000000000/tugas \
  --attribute-names QueueArn --query Attributes.QueueArn --output text)
aws lambda create-event-source-mapping --function-name pekerja \
  --event-source-arn $QARN --batch-size 5 --query State

for i in 1 2 3; do
  aws sqs send-message --queue-url http://localhost:4566/000000000000/tugas \
    --message-body "{\"id\": $i, \"menu\": \"menu-$i\"}" >/dev/null
done
sleep 5
aws logs tail /aws/lambda/pekerja --since 5m | grep memproses
"Active"
"Enabled"             ← di AWS asli: "Creating" dulu, lalu "Enabled"
… memproses pesanan #1: menu-1
… memproses pesanan #2: menu-2
… memproses pesanan #3: menu-3

Anda tidak memanggil fungsi sama sekali. Lambda (di sini Floci) yang menarik pesan dari antrean, memanggil fungsi dengan batch berisi pesan, lalu menghapus pesan jika fungsi sukses. Jika fungsi error, pesan kembali ke antrean (visibility timeout, Modul 2).

Latihan mandiri

Latihan 1. Buat fungsi kalkulator yang menerima {"a": 3, "b": 4, "op": "+"} dan mengembalikan hasilnya. Dukung + - * /, dan kembalikan pesan error yang rapi jika membagi dengan nol.
Lihat kunci jawaban 
cat > kalk.py <<'EOF'
import operator
OPS = {"+": operator.add, "-": operator.sub, "*": operator.mul, "/": operator.truediv}

def handler(event, context):
    try:
        return {"hasil": OPS[event["op"]](event["a"], event["b"])}
    except ZeroDivisionError:
        return {"error": "tidak bisa membagi dengan nol"}
    except KeyError as e:
        return {"error": f"parameter tidak dikenal: {e}"}
EOF
zip -q kalk.zip kalk.py
aws lambda create-function --function-name kalkulator --runtime python3.12 --handler kalk.handler \
  --role arn:aws:iam::000000000000:role/lambda-role --zip-file fileb://kalk.zip >/dev/null
aws lambda invoke --function-name kalkulator --cli-binary-format raw-in-base64-out \
  --payload '{"a": 10, "b": 0, "op": "/"}' h.json >/dev/null; cat h.json

Error yang ditangani di kode menghasilkan respons normal (tanpa FunctionError).

Latihan 2. Ubah fungsi pekerja agar error untuk pesanan dengan id genap. Kirim pesan id 2. Apa yang terjadi dengan pesannya?
Lihat kunci jawaban

Tambahkan if pesanan["id"] % 2 == 0: raise ValueError("gagal"), kemas ulang, lalu update-function-code. Pesan id 2 terus dicoba ulang: setiap kali gagal, pesan kembali ke antrean setelah visibility timeout. Log menunjukkan error berulang. Solusinya: pasang DLQ di antrean tugas (RedrivePolicy, Modul 2) agar pesan beracun dipindahkan setelah N kali gagal.

Kuis

1. Invoke mengembalikan StatusCode: 200 dan FunctionError: Unhandled. Artinya?
Status 200 = layanan Lambda menerima request. FunctionError = kode Anda yang gagal.
2. Kenapa invoke kedua jauh lebih cepat?
Lambda tidak menyimpan hasil. Kode tetap dijalankan, tetapi tanpa biaya membuat container dan inisialisasi.
3. Dengan event source mapping SQS, siapa yang menghapus pesan dari antrean?
Itu salah satu keuntungan ESM: Anda cukup fokus memproses isi event["Records"].

Di AWS asli, apa bedanya?

  • Biaya dihitung dari jumlah request × durasi × memori. Free Tier bulanan cukup besar untuk belajar.
  • Execution role harus benar-benar ada dan punya izin, mis. untuk menulis log dan membaca SQS (Modul 6).
  • Cold start di AWS biasanya ratusan milidetik, dan tidak ada proses pull image seperti di laptop.
