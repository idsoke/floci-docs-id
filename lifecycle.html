Siklus Hidup & Init Hooks

Apa yang dikerjakan Floci dari detik pertama dinyalakan sampai benar-benar berhenti, berdasarkan lifecycle/EmulatorLifecycle.java, dan bagaimana Anda bisa menyisipkan skrip sendiri di setiap fase.

Penjelasan sederhana

Seperti membuka toko di pagi hari: buka gembok (boot), keluarkan barang dari gudang (muat storage), nyalakan mesin-mesin (container RDS, Redis), buka pintu untuk pembeli (HTTP siap), lalu pasang papan "BUKA" (Ready). Malamnya kebalikannya: tutup pintu, catat stok terakhir ke buku (flush), matikan mesin, kunci toko. Init hooks adalah catatan tugas yang Anda titipkan untuk dikerjakan di tiap tahap, misalnya "setiap buka toko, siapkan 3 rak (bucket) dan 2 kotak surat (antrean)".

Animasi: proses startup

Detail langkah onStart (urutan di kode)

  1. Banner: versi, endpoint, region, akun, mode storage, TLS, status IAM.
  2. Hook boot dijalankan. Gagal = Floci berhenti.
  3. Validasi path persisten (PersistentPathValidator), log daftar layanan aktif.
  4. storageFactory.loadAll(): semua store dimuat dari disk sesuai mode.
  5. Bersih-bersih sesi IAM yatim: sesi role eksekusi Lambda, sesi instance EC2, sesi task-role ECS.
  6. Pemulihan: schema worker, eksekusi Step Functions yang terputus dibatalkan, eksekusi durable Lambda dipulihkan.
  7. Poller dinyalakan: SQS, Kinesis, DynamoDB Streams (event source mapping Lambda), EventBridge Pipes, Redshift zero-ETL.
  8. Runtime dipulihkan: container RDS, Timestream InfluxDB, ElastiCache (Redis & Memcached), ELBv2, ELB Classic, ECS.
  9. Server metadata: EC2 IMDS dan server kredensial task-role ECS (jika dibutuhkan).
  10. Jika tidak ada hook start/ready: langsung tandai siap dan cetak === AWS Local Emulator Ready === + Ready.

Saat server HTTP benar-benar listen (onHttpStart): kluster EKS yang tersimpan dipulihkan, hook start lalu ready dijalankan, kemudian banner Ready dicetak.

Kenapa ada baris "Ready."? Testcontainers LocalStackContainer menunggu log yang cocok dengan regex .*Ready\.. Floci mencetaknya demi kompatibilitas dengan LocalStack (bisa dimatikan lewat pengaturan paritas LocalStack).

Animasi: proses shutdown

Setiap langkah pembersihan dibungkus runCleanup(nama, aksi): kegagalan dicatat lalu dilanjutkan ke langkah berikutnya, supaya satu container yang macet tidak menghalangi flush storage.

Init hooks

FaseKapanAPI AWS tersedia?Folder FlociFolder kompatibel LocalStack
bootSebelum storage dimuat dan layanan mulai❌/etc/floci/init/boot.d/etc/localstack/init/boot.d
startSetelah HTTP di 4566 siap✅/etc/floci/init/start.d/etc/localstack/init/start.d
readySetelah semua hook start selesai✅/etc/floci/init/ready.d/etc/localstack/init/ready.d
stopPre-shutdown, HTTP masih hidup✅/etc/floci/init/stop.d atau shutdown.d/etc/localstack/init/shutdown.d
  • Ekstensi: .sh (shell, default /bin/sh), .py (python3). Di Windows juga .ps1, .cmd, .bat.
  • Urutan: leksikografis dan berurutan. Beri awalan angka: 01-, 02-.
  • Fail-fast: skrip yang exit non-zero menghentikan sisa skrip di fase itu. Gagal di boot/start/ready → Floci mati. Gagal di stop → hanya dicatat.
  • Jika nama file sama ada di kedua folder, versi Floci yang dijalankan.
  • Status tiap fase bisa dipantau di /_floci/init dan /_localstack/init.
  • Image floci/floci:latest-compat sudah berisi AWS CLI dan boto3 yang mengarah ke localhost:4566.

Contoh: seed resource otomatis

# init/ready.d/01-seed.sh
#!/bin/sh
set -eu
aws s3 mb s3://unggahan
aws sqs create-queue --queue-name pesanan
aws dynamodb create-table --table-name pengguna \
  --attribute-definitions AttributeName=pk,AttributeType=S \
  --key-schema AttributeName=pk,KeyType=HASH --billing-mode PAY_PER_REQUEST
aws ssm put-parameter --name /app/env --type String --value lokal
# docker-compose.yml
services:
  floci:
    image: floci/floci:latest-compat
    ports: ["4566:4566"]
    volumes:
      - ./init/ready.d:/etc/floci/init/ready.d:ro
